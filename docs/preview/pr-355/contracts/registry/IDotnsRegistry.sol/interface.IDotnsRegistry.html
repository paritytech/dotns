IDotnsRegistry

Git Source

Title: IDotnsRegistry

Author: Parity

Minimal on-chain registry for hierarchical name ownership and resolution.

Tokenised second-level nodes are owned through the registrar (ERC-721); subnodes are owned directly by the address stored in Record.owner.

Note: security-contact: admin@parity.io

Functions

setSubnodeOwner

Creates or reassigns a subnode and assigns its owner.

Callable only by the current owner of record.parentNode, otherwise

Notes:

  • reverts: NotAuthorised. The new owner address must be non-zero, otherwise

  • reverts: NotAllowed. record.subLabel must be a single canonical DNS label (otherwise @custom:reverts InvalidLabel) and record.parentLabel must be a name path of at most StringUtils.MAX_NAME_PATH_OCTETS octets whose namehash matches record.parentNode (otherwise

  • reverts: ParentLabelMismatch). Subnodes are parent-sovereign: the current record.parentNode owner may reassign or rotate a subnode's resolver at any time without the prior subnode owner's consent. On reassignment the resolver pointer is reset to the protocol-registered default reverse resolver so a prior subnode owner's resolver cannot be inherited by the next holder (records on other resolver contracts are keyed by node and are not cleared by this function; downstream consumers should gate resolver reads on current ownership). Indexes the subnode under the new owner's LabelStore keyed by the namehashed subnode so off-chain consumers can enumerate names per address. Indexing into the owner's LabelStore is governed by record.persist (see @custom:struct SubnodeRecord); the ownership and resolver record is written either way. A record.persist of false defers the store write and is restricted to registered controllers (@custom:function IDotnsRegistrar.controllers), otherwise @custom:reverts NotAuthorised. Creating a subname, as opposed to reassigning one that resolves, requires it to sit at most MAX_SUBNAME_DEPTH levels below its second-level name, otherwise @custom:reverts SubnameTooDeep. A subname still on record but cut off by a clear above it is created again from nothing: its versions are bumped, emitting

  • emits: RecordsCleared and @custom:emits SubnamesCleared, so none of its old records or subnames come back. Emits @custom:emits NewOwner on each successful assignment.

function setSubnodeOwner(SubnodeRecord calldata record) external returns (bytes32 subnode);

setSubnodeResolver

Sets the resolver for an existing subnode.

Callable only by the current owner of record.parentNode, otherwise

Notes:

  • reverts: NotAuthorised. The subnode owner can still update the resolver directly via setResolver. Both entry points emit the same NewResolver(subnode, ...) event, so the parent can silently override a subnode owner's chosen resolver: this is the parent-sovereign hierarchy applied to resolution. Off-chain consumers that surface trust signals to subnode owners should treat any resolver rotation as a re-attestation prompt. record.subLabel must be a single canonical DNS label (otherwise @custom:reverts InvalidLabel) and record.parentLabel must be a name path of at most StringUtils.MAX_NAME_PATH_OCTETS octets whose namehash matches record.parentNode (otherwise

  • reverts: ParentLabelMismatch). The resulting subnode must exist and resolve, otherwise @custom:reverts NotAuthorised. Emits @custom:emits NewResolver on success.

setOwner

Creates or resets a node record for a tokenised second-level registration.

Restricted to the registrar's controllers, otherwise @custom:reverts NotAuthorised. newOwner must be non-zero (otherwise @custom:reverts NotAllowed) and must match the ERC-721 owner reported by the registrar (otherwise

Notes:

  • reverts: NotAuthorised). The function is callable both on a fresh registration and on every reclaim from escrow: each call rewrites records[node].resolver to the protocol-registered default reverse resolver so a prior owner's resolver pointer (and the records keyed under it) cannot be inherited by the next holder across that recycle. A secondary-market ERC-721 transferFrom does not call the registry, so a name sold directly keeps the seller's resolver pointer until the buyer overwrites it. That covers the node itself and not the nodes beneath it: a subname stores its own owner, and @custom:function isAuthorised returns on that owner before consulting the registrar, so after the sale the seller keeps write authority over every subname whose stored owner is still the seller, until the buyer deletes each one through @custom:function deleteSubname or clears them all at once through @custom:function clearSubnames. Reassigning one through

  • function: setSubnodeOwner keeps its records and the subnames beneath it. A subname created for someone else stays with that owner and leaves the seller no write path. The set is derivable from

  • emits: NewOwner, which indexes the parent node. Stores owner = address(0) as a sentinel so reads delegate to IDotnsRegistrar.ownerOf and ERC-721 transfers remain authoritative. Emits

deleteSubname

Deletes one subname of parentNode, together with its records and every subname beneath it.

Callable by anyone @custom:function isAuthorised admits for parentNode, otherwise

Notes:

  • reverts: NotAuthorised: subnames are parent-sovereign, so the parent decides, not the subname's holder. The subname's record and parent link are zeroed, releasing their storage deposit to the signer of the transaction; one version slot stays so the subname, created again, starts empty. The subname need not resolve: one a clear has already cut off can still be deleted by whoever controls parentNode now, after a transfer included. Subnames beneath it are cleared but keep their storage, and once their own parent stops resolving nobody can delete them, so freeing every deposit means deleting from the deepest subname up, each by whoever holds that subname's parent, before clearing anything above them. A subname must exist there, otherwise

  • reverts: SubnameNotFound. Emits @custom:emits NewOwner with a zero owner, the deletion convention indexers already follow, and @custom:emits RecordsCleared and

  • emits: SubnamesCleared for the subname.

linkSubname

Records the parent of a subname whose parent was never recorded, so that clearing an ancestor reaches it.

Permissionless: the parent is proven by the namehash, since subnode is keccak256(parentNode, labelhash), so a caller cannot link a subname anywhere else. The subname is linked as created under its parent's first subname version, so a subname whose ancestor was cleared before it was linked reads as cleared once it and every level between it and that ancestor are linked; an unlinked level still ends the walk as resolving. Every successful write path that keeps the subname and names its parent (@custom:function setSubnodeOwner, @custom:function setSubnodeResolver) links it as a side effect; this entry point covers the rest. @custom:reverts SubnameNotFound when no subname exists there. A subname already linked is left as it is. Emits

Note: emits: SubnameLinked when it links.

recordVersion

Returns whether node resolves and the record version its records are written under.

Resolvers stamp each write with recordsVersion and treat a record whose stamp differs, or any record of a node that does not resolve, as unset. A tokenised name resolves while its record exists; a subname resolves while no ancestor has cleared or deleted it. Version 0 is the version every node starts at, and a record stamped 0 matches it, so a node that was never cleared reads every record stamped 0. Checking a subname walks its ancestors, so the cost grows with its depth.

Thrown when a sublabel is not a canonical lowercase ASCII DNS label.

ParentLabelMismatch

Thrown when the supplied parent label does not match the parent node, or is not a valid name path.

The two cases share one error because both mean the caller's parentLabel cannot be trusted to name parentNode: a mismatched namehash, a malformed segment, or a path over StringUtils.MAX_NAME_PATH_OCTETS. That last bound is on the path in octets, so it limits nesting only through how much of the budget each level spends. It exists because the composed full name is stored in a LabelStore row that has no delete path.

error ParentLabelMismatch();

Structs

SubnodeRecord

Record describing a subnode creation request.

struct SubnodeRecord {
    bytes32 parentNode;
    string subLabel;
    string parentLabel;
    address owner;
    bool persist;
}

Properties

NameTypeDescription
parentNodebytes32
subLabelstringHuman readable subnode label e.g "alice".
parentLabelstringCanonical parent name without the TLD suffix e.g. bob or child.bob. At most StringUtils.MAX_NAME_PATH_OCTETS octets. The bound is on the path in octets, so it limits nesting only through how much of that budget each level spends.
owneraddressAddress to assign as owner of the created subnode.
persistboolWhether to index the subnode into the owner's LabelStore, deploying it on demand. When false the ownership and resolver record is still written but the store is left untouched, and an authorised store writer backfills the label later by deploying the owner's store and writing to it. Deferring the store write this way is restricted to registered controllers (@custom:function IDotnsRegistrar.controllers): any other caller must pass true, otherwise @custom:reverts NotAuthorised, because it could never backfill a deferred label. The registry writes the store only on creation or on a reassignment to a new owner, so a later same-owner re-call with true does not backfill it; the authorised writer backfills it directly.
