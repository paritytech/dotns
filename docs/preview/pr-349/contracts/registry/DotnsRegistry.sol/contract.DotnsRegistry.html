DotnsRegistry

Git Source

Inherits: Initializable, UUPSUpgradeable, OwnableUpgradeable, IDotnsRegistry

Title: dotNS Registry

Author: Parity

Upgradeable on-chain registry for hierarchical name ownership and resolution.

Tokenised second-level nodes store owner == address(0) as a sentinel and defer to IDotnsRegistrar.ownerOf; subnodes carry an explicit owner address in records.

Note: security-contact: admin@parity.io

Constants

MAX_SUBNAME_DEPTH

Deepest a new subname may sit below its second-level name: a subname directly under alice is at depth 1, one under child.alice at depth 2.

Bounds the read cost, not the clear cost. Clearing is constant at any depth, but deciding whether a subname still resolves walks every level above it, and every read of a subname (owner, authority, each resolver record) pays that walk. Checked only when a subname is created, so a deeper subname that already exists keeps working.

uint256 public constant MAX_SUBNAME_DEPTH = 8

linkSubname

Records the parent of a subname whose parent was never recorded, so that clearing an ancestor reaches it.

Permissionless: the parent is proven by the namehash, since subnode is keccak256(parentNode, labelhash), so a caller cannot link a subname anywhere else. The subname is linked as created under its parent's first subname version, so a subname whose ancestor was cleared before it was linked reads as cleared once it and every level between it and that ancestor are linked; an unlinked level still ends the walk as resolving. Every write path that names a parent links it as a side effect; this entry point covers the rest. @custom:reverts SubnameNotFound when no subname exists there. A subname already linked is left as it is. Emits @custom:emits SubnameLinked when it links.

recordVersion

Returns whether node resolves and the record version its records are written under.

Resolvers stamp each write with recordsVersion and treat a record whose stamp differs, or any record of a node that does not resolve, as unset. A tokenised name resolves while its record exists; a subname resolves while no ancestor has cleared or deleted it. Version 0 is the version every node starts at, and a record stamped 0 matches it, so a node that was never cleared reads every record stamped 0. Checking a subname walks its ancestors, so the cost grows with its depth.

Structs

NodeVersions

Versions that let a node, or everything beneath it, be cleared at constant cost.

Neither records nor subnames can be listed, so clearing never visits them. It bumps a version instead, and readers compare against it:

  • records is the version a node's resolver records are stamped with. Bumping it makes every record of the node read as unset.
  • subnames is the version a new child is created under. Bumping it makes every child, and through them every deeper subname, stop resolving.
  • parentSubnames is the parent's subnames at the moment this subname was created. Kept apart from records because @custom:function setOwner rewrites a whole Record, and a version reset to zero would bring back every record written under it.
struct NodeVersions {
    uint64 records;
    uint64 subnames;
    uint64 parentSubnames;
}
