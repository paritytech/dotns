Title: Dotns Name Escrow Interface

Escrows refundable deposits for .dot registrations and manages the release lifecycle.

Canonical escrow state is keyed by tokenId. A token may be funded with a refundable deposit, released into escrow, withdrawn after cooldown by the snapshotted recipient, and reclaimed by a new registrant via the controller during re-registration.

Note: security-contact: admin@parity.io

deposit

Records an asset deposit position for a token.

Callable only by the registrar controller. The call value must equal amount. The recipient field on params is locked at deposit time and is the only address eligible for the refund via withdraw(). The controller must pass the registrant's refund address (typically the original msg.sender of register).

We trust that the controller passed amount since it handles refunds

Callable only by the registrar controller. Used when msg.sender != registration.owner AND tier prices differ — the controller forwards the differential to the escrow so the original payer is recorded for the event and the running max is bumped to keep transfer-time fee accounting consistent.

chargeTransferFee

Charges the cross-tier transfer-fee delta against the running max for a token.

Authorised only for the registrar resolved from the protocol registry.

Note: contract: IDotnsProtocolRegistry.get Atomic: reads runningMax, computes delta, updates state, deposits to insuranceFund, refunds excess to payer. If priceForTo <= runningMax[tokenId], the recipient is already covered and msg.value is fully refunded; the function returns 0. Otherwise delta = priceForTo - runningMax[tokenId] is charged from msg.value; the running max bumps to priceForTo; insurance increments by delta; any overpayment is refunded. Reverts InsufficientValue when msg.value < delta for a cross-tier downgrade.

withdraw

Credits the refundable deposit for a released token to the recipient's pending balance.

Pull-payment: this function does NOT send native value. It marks the position as claimed, debits tokenReserved (and the insurance fund on shortfall), and credits the recipient's _pendingWithdrawals entry. The recipient must subsequently call claimWithdrawal() to pull the funds.

Note: emits: RefundWithdrawn when the credit is recorded.

function withdraw(uint256 tokenId) external;

Parameters

NameTypeDescription
tokenIduint256Token identifier.

claimWithdrawal

Pulls the caller's accumulated pending refund balance.

Implements the second half of the pull-payment refund flow. The caller's pending balance is zeroed before the external call to enforce checks-effects-interactions. A single call drains the entire pending balance, which may aggregate multiple withdraw() credits.

Notes:

  • reverts: NoPendingWithdrawal if the caller has no balance to pull.

  • reverts: RefundFailed if the native transfer fails.

  • emits: WithdrawalClaimed with the pulled amount.

function claimWithdrawal() external returns (uint256 amount);

ChargeTransferFeeParams

Inputs for charging a cross-tier transfer fee.

Routed via the registrar's payable ERC721 transfer entrypoints from _update. The struct keeps the call site self-documenting and matches the project idiom of structs for >=4 params.

Notes:

  • contract: IPopRules.priceWithoutCheck

  • contract: IPopRules.reachFee

struct ChargeTransferFeeParams {
    uint256 tokenId;
    uint256 priceForTo;
    uint256 reachFloor;
    address payer;
    address to;
}

Properties

NameTypeDescription
tokenIduint256Token being transferred.
priceForTouint256Recipient-tier price quoted from PopRules. Drives the running-max delta path: max(priceForTo - runningMax, 0).
reachFlooruint256Length-scaled friction owed when the recipient cannot meet the label's required tier (verified-but-below). Forms a floor on the charge: fee = max(delta, reachFloor). Pure-friction charges (delta zero, floor non-zero) credit insurance without bumping the running max.
payeraddressThe original msg.sender of the registrar transfer entrypoint.
toaddressNFT recipient (used in event emission for indexer clarity).
